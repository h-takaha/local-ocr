# セットアップと確認

まずOllamaとlocal-ocrを同じPCで動かし、そのPCのブラウザで公開サンプルを試します。
WindowsのPowerShellを基本とします。Mac/Linuxで同等の構成を試す場合も、
本アプリのOCRはそれらの環境で未検証です。

インストールやモデルのダウンロードを始める前に、
[動作確認済みPCの構成](../README.md#ダウンロード前に確認) と [検証記録](VALIDATION.md) を確認してください。
確認済みの構成は最低スペックではなく、未検証の環境を非対応と判定したものでもありません。

## 1. 実行環境を用意する

- Node.js 24以上: [公式ダウンロード](https://nodejs.org/en/download)
- Ollama: [公式ダウンロード](https://ollama.com/download)
- Git、ブラウザ

Ollamaを起動してから確認します。

```powershell
node --version
ollama --version
ollama list
```

モデルがなければダウンロードします。これは外部への通信とディスクへのモデル保存を伴います。

```powershell
ollama pull qwen3.5:9b
```

必要RAM/VRAM・空き容量はモデルと実行条件で異なります。
本アプリにおける最低スペックやCPU実行の所要時間は未確定です。
モデルサイズを必要メモリ量と同一視しないでください。

Ollama公式ではWindowsは10 22H2以降、macOSはSonoma 14以降を案内しています
（[Windows](https://docs.ollama.com/windows)、[macOS](https://docs.ollama.com/macos)、2026-10-17確認）。
対応GPU・ドライバーは [GPUの公式条件](https://docs.ollama.com/gpu) を確認してください。
これらはOllamaの条件であり、本アプリのOCR動作確認とは別です。

## 2. リポジトリと認証を用意する

GitHubの「Code」で示されるURLを使ってcloneし、local-ocrフォルダーへ移動します。
以降のコマンドは `server.mjs` のあるフォルダーで実行します。

```powershell
Copy-Item .env.example .env
notepad .env
```

既存の `.env` があればコピーで上書きせず、内容を確認します。
`BASIC_AUTH_USER` と、空でない `BASIC_AUTH_PASSWORD` を設定して保存します。
標準構成では接続先は `http://127.0.0.1:11434` です。
`.env` は秘密を含む個人設定なのでコミット・共有しません。

Nodeへ設定を渡すには、以降の起動・診断で `--env-file=.env` が必要です。
アプリ側の `npm install` は不要です。

## 3. 診断して起動する

```powershell
node --env-file=.env server.mjs doctor
node --env-file=.env server.mjs doctor --json
node --env-file=.env server.mjs serve --port 8005
```

診断ではOS/RAM、Node/Ollamaバージョン、選択モデルのサイズ・vision対応・local判定、
ロード中モデルのCPU/GPU配置などを、取得できる範囲で確認します。
GPU型番・ドライバー・空きVRAM・空きディスク容量は自動診断では未確認です。
未取得・未ロードの項目を、推測で対応済みと解釈しないでください。
Ollamaにモデルがあることと、その画像のOCRが成功することは別です。

サーバーを起動したPowerShellを開いたまま、
[http://127.0.0.1:8005](http://127.0.0.1:8005) をブラウザで開きます。
認証ダイアログには `.env` で設定したユーザー名とパスワードを入力します。
終了はそのPowerShellで `Ctrl+C` を押します。

## 4. サンプルでOCRを確かめる

「サンプルで試す」を押し、プレビューを確認して「文字を抽出する」を押します。
「サンプルの正解を確認」を開くと期待本文を読めます。
「読みにくい例を試す」で薄い文字の例も比較できます。
結果を期待本文と照合し、本文の編集・コピー・TXT保存も試してください。

初回はモデル読み込みを含むため時間がかかる場合があります。
画面の経過時間とモデル読み込み時間を分けて確認します。
画像条件、モデル、配置、ロード状態で所要時間は変わり、過去の実測値は保証値ではありません。
検証条件と結果は [VALIDATION.md](VALIDATION.md) を参照してください。

## うまく動かないとき

| 症状 | 確認すること |
|---|---|
| `node` / `ollama` が見つからない | インストール後にPowerShellを開き直し、バージョンを確認 |
| Nodeが古い、`--env-file` が使えない | Node.js 24以上か確認 |
| 401、何度も認証を求められる | `.env` のパスワード、`--env-file=.env`、入力したユーザー名を確認 |
| Ollamaに接続できない | Ollamaを起動し、`doctor` と接続先設定を確認 |
| モデルが見つからない | `ollama list` と `LOCAL_OCR_MODEL` を照合。必要なモデルをpull |
| vision対応/local判定が未確認/非対応 | 画像送信を止める仕様。ローカルで画像入力に対応するモデルか配布元と診断で確認 |
| GPU配置が未確認 | サンプル実行後に診断を更新。未ロード状態からCPU/GPU配置を推定しない |
| 429 | 別のOCR終了を待つ。同時処理は1件 |
| 504、長時間終わらない | 画像の文字量・サイズ、モデル読み込み、メモリ配置を確認し、小さいサンプルで比較 |
| `ollama_memory` | Ollamaがメモリ確保失敗を報告。他の負荷や配置を確認する。別モデルへ自動切替はしない |
| `ollama_error` / `ollama_busy` | 原因は未確認。診断を更新し、Ollamaの状態・手元のログを確認する |
| HEICを開けない | JPEG/PNG/WebP等へ変換して試す |
| 誤読する | 書類部分を切り出す、正面から明るく撮る、通常/高精度を比較する |
| ポート8005を使用できない | 既存サーバーを確認するか `serve --port 8006` 等へ変更し、そのURLを開く |

診断データは画像・OCR本文・認証情報・ホスト名・個人パスを含まない設計です。
不具合を報告する場合も、`.env` や個人の書類は添付せず、再現用の架空画像と診断結果を使います。
このリポジトリのGitHub Issuesへ、OS・再現手順・期待した結果・実際のエラーコードと診断JSONを添えてください。
Issuesが利用できない場合は、作品を案内した窓口へ同じ項目を伝えてください。
送信前に診断の内容を自分でも確認し、Ollamaの生ログ全体は添付しないでください。

## スマホから使う場合

同じPCでOCRを確認した後、PCへ到達できるネットワークとHTTPS配信を用意します。
Tailscale等のプライベートネットワークを使う構成は任意です。
本リポジトリはVPN・HTTPS・ルーター・ファイアウォール設定を自動変更しません。

標準待受 `127.0.0.1` は別端末から到達できません。
`--host 0.0.0.0` は同一LANにも公開するため、到達範囲・認証・HTTPSを確認してから選びます。
Basic認証はHTTP通信を暗号化しません。インターネットへ直接ポート開放する運用は想定しません。
PCは起動し、スリープしていない必要があります。

Android Chromeで同じoriginのHTTPS URLを開いて認証した後、
「アプリをインストール」または「ホーム画面に追加」で登録できます。
オフライン動作・Service Worker・OCR履歴保存はありません。
HTTPS設定、Android実機の登録・再起動、モバイル回線での利用は、それぞれ別途検証が必要です。

## 既存ディスパッチャ構成

単体導入には不要です。既存のOllama互換ディスパッチャを使う場合だけ、
`.env` に `LOCAL_LLM_DISPATCHER_URL` を明示します。
この変数は `OLLAMA_BASE_URL` より優先されます。
接続先を変更すると、画像とOCR指示の送信先も変更されます。
診断APIの一部を中継しないディスパッチャでは取得できない項目があり、未確認として扱います。
