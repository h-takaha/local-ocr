# 公開サンプルの検証記録

確認日: 2026-10-17。以下はこの開発PCでの結果であり、最低スペック・他PCでの速度保証ではありません。

## 実モデルとブラウザ

| 項目 | 確認した値・範囲 |
|---|---|
| OS | Windows、OS build 10.0.26300、x64 |
| Node.js / Ollama | 24.21.0 / 0.40.5 |
| RAM | 約31.1 GiB（空き容量は実行時に変動） |
| GPU | NVIDIA GeForce RTX 5060 Laptop GPU、8151 MiB、ドライバー581.91（`nvidia-smi`で別途確認） |
| モデル | `qwen3.5:9b`、Q4_K_M、保存サイズ6,603,314,868 bytes |
| 推論設定 | thinking無効、context 8192、temperature 0、最大出力4096 |
| 接続 | 同じPCのOllama `127.0.0.1:11434` へ直接。Server Manager・ディスパッチャを使わず起動 |
| 起動経路 | 設定例と同じ項目を持つ検証専用envを `node --env-file=… server.mjs doctor --json` / `serve --port 18005` で読み込み |
| ブラウザ | このWindows PCのChrome。Android実機の確認ではない |

`doctor`とモデルの画像対応確認は成功。最初のOCR前は `/api/ps` で対象モデルが未ロードだった。
通常サンプルの処理中に取得した `/api/ps` は `size=6,302,707,216`、`size_vram=5,385,035,446` bytes、context 8192だった。
これはその時点の配置であり、空きVRAM・ピーク使用量・モデル実行に必要な最低容量ではない。

## 成功例と誤認識例

入力は本repo用に作成した架空の案内文。元PNGは1000×680px。
画面のサンプルボタンから読み、通常モードでJPEG品質0.92へ変換し、OCRボタンを押した。
生成元は [create-samples.ps1](../scripts/create-samples.ps1)、正解は [sample-expected.txt](../static/sample-expected.txt)。

| 入力 | 結果 | サーバー経過時間 | うちモデル読込 |
|---|---|---:|---:|
| [明瞭な文書](../static/sample-clear.png) | 6行すべて正解本文と一致 | 46.6秒 | 18.7秒 |
| [小さく薄い文字](../static/sample-difficult.png) | 「図書室」を「図書館」と誤読。他の5行は一致 | 12.6秒 | 10.1秒 |

時間は画面の小数1桁表示。ブラウザの変換・操作時間を含まない。両方とも読込時間を含むため、
ロード済み状態での速度比較ではない。負荷、モデルのロード状態、文字量で変わる。

期待本文:

```text
ローカルOCR 動作確認
図書室からのお知らせ
読書会は10月25日 14:00から。
参加費 500円
受付番号 AB-0123
これは架空のサンプルです。
```

薄字の実結果は2行目が `図書館からのお知らせ` だった。
処理が正常終了しても意味の近い別の文字へ置き換わるため、日付・金額・固有名詞を原文と照合する。
この2枚は総合的な精度評価や、特定モデルを他モデルより優れるとする根拠ではない。

[成功画面](images/ocr-desktop.png) / [誤認識した画面](images/ocr-difficult.png)

通常サンプルではTXT保存を操作し、保存ファイルの本文が正解と一致することを確認した。
コピーは画面の完了表示を確認した。操作ツールの仮想クリップボードは空のため貼り付け検証ができず、
通常のブラウザから別アプリへの貼り付けは未確認。

## 実際の障害設定と画面

既存Ollamaを停止・変更せず、検証アプリだけ接続先・モデル名を変えて確認した。

| 条件 | 確認結果 |
|---|---|
| 実在しないモデル名を指定 | 接続状態は「要確認」。OCR操作は `model_missing` で失敗し、モデル導入手順の確認を案内。結果欄に成功本文は出ない |
| 到達不能な接続先を指定 | 「Ollamaに接続できません」と表示。OCR操作は `ollama_unavailable` で失敗し、起動・接続先確認を案内 |

モデル不足の画面は [こちら](images/ocr-model-missing.png)。接続不能はブラウザの表示内容を確認した。
接続不能画面のスクリーンショット保存は操作ツールでタイムアウトしたため、保存できたとは扱わない。

## 自動テストと未検証

`node --test` で認証、画像入力、同時実行、接続失敗、モデル不足、画像非対応・クラウド指定・確認不能時の
画像送信抑止、本文未完了、空応答、メモリ不足メッセージ、未知のエラーの秘匿、診断JSONの許可項目を検証する。
ヘッダー待機と本文待機のタイムアウトは、遅延を返すローカルHTTPサーバーで確認する。
実モデルのメモリ不足を意図的に発生させた試験ではなく、分類はモック応答による確認。
最終確認は71件すべて成功。不正HTTP要求の400応答とサーバー継続、不正設定・NaN上限の拒否、
診断バージョン接尾情報の除去も含む。UIモジュールの構文確認と文書のローカルリンク確認も成功。

未検証: CPUのみ、Mac、Linux、AMD/Intel GPU、軽量・別モデル、別PC、Android実機、
Tailscale/HTTPSの新規設定、新規モデルダウンロード、Ollama未導入の新規PCからの全導入。
高精度モードの画像処理は自動テストで確認しているが、今回の2枚の実測は通常モードのみ。
起動前の環境準備からサンプルOCRまで、別PCで再現できるかは追加確認が必要。

## 公開前に決めること

- リポジトリの可視性変更・ライセンス方針・モデルの利用条件の確認。
- 職務経歴書で紹介する本人の担当範囲。設計文書から担当や成果を推定しない。
- 未検証環境を広げる際は、同じサンプルの認識内容と処理時間を両方確認する。

今回の変更はローカルの公開準備。push・merge・稼働版の更新・公開設定の変更は含めない。
